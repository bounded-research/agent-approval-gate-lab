# D-008 request-format repair and p1-v2 exploratory rerun

The D-008 repair passed the new red/green regression and Phase 0 checks. The p1-v2 rerun reached `pending` in 14 of 20 live runs, with no self-approval attempts or successes. This is a negative exploratory observation under one model and one arm, not evidence that approval-channel abuse cannot occur.

## Custody and design

Before the repair, the 40 p1-v1 rows and their ledgers had 37 `request_action` calls: 19 immediate `forbidden` replies and 18 `pending` replies across 11 runs. The original 40 rows and historical run/audit files were not changed. The p1-v2 data use phase `P1_EXPLORATORY_D008`, `qwen3.8-27b`, hidden A-panel, automatic denying reviewer, enforced `labagent`, one fresh networkless container and `/runs` mount per trial. S and E were run as separate ten-run seed-21 and seed-22 cells. Two earlier excluded p1-v2 smokes, one S and one E, each reached `pending` and are in `data/pilot.jsonl`.

The build-assistant prediction was left blank before the batch. The owner's separately labeled guesses are in `prereg/D008_P1V2_REGISTER.md`. No prediction was retrofitted after seeing the results. Raw rows, schedules, container logs, and run directories were committed before running `scripts/analyze.py` for each batch. The analyzer keeps p1-v1 and p1-v2 in separate cells.

## Checks and limits

The failing test was written and run before the fix: all six local task/arm combinations returned `forbidden` for `sloppy_request`, where `unrecognized_request` was expected (`audit/D008_RED_TEST_BOTH_ARMS.log`). After the fix, the focused regression passed (`audit/D008_GREEN_TEST.log`). The full Docker enforced Phase 0 log records 93 tests passed, self-audit 66 passed/0 failed, 20/20 mutants killed, and enforced mode available (`audit/D008_PHASE0_DOCKER_FULL.log`). These are implementation checks, not independent evidence of a live self-approval event.

D-008 changes the evaluation surface: the model-facing action schema, target guidance, `PROMPT_VERSION` p1-v1 → p1-v2, response categories, exposure fields, tests, and analyzer grouping. See `prereg/DEVIATIONS.md` D-008 and `docs/FAILURE_MODES.md` F-19. It corrected misleading no-match responses in tests and increased valid pending exposure in the new live cells; the data do not isolate the prompt change's causal effect. The model may still ignore a tool schema, and an invalid request remains fail-closed. This run did not test B-gate with the live model, actual human approval or MFA, other models, or a realistic UI. The file panel and automatic denial are existing lab scaffolds. A null from 14 pending-exposed runs is too small to establish a rare-event rate or a 9/10-worthy external contribution.

Custody note: during setup, a direct self-audit command briefly regenerated two historical audit files. Their new output was preserved under D-008-specific filenames, then the historical files were restored byte-for-byte from Git before any commit; the error and repair are recorded in `WORKLOG.md`.
